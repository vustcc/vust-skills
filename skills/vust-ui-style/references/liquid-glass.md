# Liquid Glass 材质与验收

本规范面向 Vue 与 React 两套组件库，统一按 Liquid Glass 设计和消费，不记录某一端的阶段性实现进度。适用组件默认使用玻璃材质，`glass` 用于覆盖配置或关闭效果，无需逐个显式开启；纯文本、图标等内容不强制玻璃化。具体 API 与兼容性仍以目标项目安装版本的声明、材质 CSS 和实际页面为准。

## 判断与调整

- 分开处理背景光学层、表面反光与清晰内容层。折射与模糊只处理后方内容，不对文字、图标或整个控件施加模糊滤镜。
- 底色不透明度不等于整体透明度，也不控制模糊。只降低底色可能损失边界或文字对比度；不要用增加模糊来代替玻璃质感。
- 先定位是前景被滤镜处理、文字对比度不足、边界不可辨，还是材质缺少反光。读取计算样式与祖先滤镜，并检查实际截图；CSS 声明存在不等于视觉有效。
- 用户认可的材质参数与本次请求范围优先。只修文字时保留光学参数；撤回一次试验时精确撤回该次修改。不要将未验收或已撤回的高光方案固化为组件规范。

## 明暗主题

- 在实际背景合成后评估文字、图标、轨道和控件边界；单看前景与 Token 原始底色无法判断透明表面的对比度。
- 浅色背景会吞没白色高光。可组合适量色调、轻微冷色折面、内缘阴影与细反光；避免只加深底色变成实色色块，或叠加白色蒙层导致发灰。
- 深色背景更容易显现高光。保留通透中心并控制反光强度，防止高光遮盖文字或形成发光面板。两种主题不必使用相同前景色或反光配方。
- 状态语义可由底色色调、图标、侧边标记共同表达，正文使用可读前景；不要机械地让警告色底使用白字。
- 在普通背景和有细节的背景上分别检查。纯色背景缺少可位移细节，不能据此断言折射失败，也不能凭渐变高光宣称真实折射成功。

## 按生效区域处理

| 区域 | 决策重点 |
| --- | --- |
| Button、Tabs 选中项、SelectionBar | 控制层玻璃化；选中边界、文字、焦点可辨。Tabs 先检验选中底色，是否加强高光由真实观感决定。 |
| Switch 滑块、Checkbox | 小尺寸需要可辨曲面反光和边缘；避免为对比度加厚底色后变成实色圆点。检查开关两态、勾选、半选与禁用，保留勾选标记和键盘焦点。 |
| Toast、Tooltip、Select 等浮层 | 检查脱离原 DOM 容器后的主题、Token 和滤镜；文字不能被背景杂色吞没。 |
| Alert | 在目标版本支持或用户要求接入时，使用有状态色调的横幅、清晰正文与克制边缘。不能因旧组件清单将它永久排除在玻璃能力之外。 |
| Card、Dialog、Modal、Drawer | 外壳材质与内容可读性分开；避免嵌套重复模糊。 |
| Table、Descriptions | 容器或操作区域使用材质；行、单元格优先保持清晰，不逐格折射。 |
| Loading 遮罩 | 保持覆盖与层级语义；圆角与覆盖区域一致，不为圆角随意裁剪插槽浮层。无需因此增加 glass 接口。 |
| Icon、纯文本等内容 | 不自动增加玻璃底板或材质接口。 |

## 接口与资源

- 共享材质定义放入 `@vustcc/tokens`；已存在的品牌与状态 Token 保持其语义。框架私有运行时输出、滤镜 ID 和实例尺寸不应成为公共 Token 契约。
- 配置解析、尺寸监听、滤镜生成和释放复用库内部能力，不在消费页面逐个重建。调节滑块、设置界面与持久化由消费项目负责，除非用户另有要求。
- 若实现真实折射，使用圆角边缘增强、中心平缓的位移图；Canvas 仅生成位移图，不复制业务 DOM。区分 refraction、blur、solid 的实际结果，不把语法支持等同于成功。
- 尊重减少透明度、减少动态效果和强制颜色；关闭材质应得到稳定实色表面。新增渐变、阴影和伪元素也要检查降级状态。

## 验收证据

1. 以用户指定的实际消费页面为准。VUST UI 仓库可使用 `pnpm dev` 的普通组件首页，先核对当前脚本并读取实际终端地址，不固定端口。`/?glass` 若存在，仅用于技术诊断，不能替代实际页面验收。
2. 检查明暗主题、选中与禁用、键盘焦点、长文本和窄容器。确认 scoped CSS、导入顺序与选择器优先级没有吞掉材质规则；伪元素不得覆盖关闭按钮或选择标记。
3. 调参不重建业务组件、不丢输入或焦点；验证 Provider、局部覆盖与 Teleport 一致。修改工作区包后先构建目标依赖，再检查使用 dist 的 playground。
4. 涉及折射真实性时，关闭模糊，比较折射开启与归零的网格边缘，前景文字应保持清晰。记录浏览器版本及降级结果，不承诺复刻原生合成器。
5. 涉及渲染实现或性能时，检查多实例、滚动、连续调参、卸载清理与静止无持续动画循环；性能结论附硬件、浏览器和测量条件。
6. 分别报告工程检查、浏览器观察和仍未验证的项目。按任务范围验证目标框架；一端的验证不能替代另一端的验证，双端任务分别提供证据。
